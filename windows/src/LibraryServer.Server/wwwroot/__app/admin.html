    ネットワーク

    ビューアの高品質縮小エンジンを wasm-vips (Filter ポップアップの「HQ engine: wasm-vips」/ ?vips=1) に切り替える場合にだけ必要です。 wasm-vips はマルチスレッド WebAssembly で動き、そのために使う SharedArrayBuffer をブラウザは「クロスオリジン分離」されたページ (Cross-Origin-Opener-Policy: same-origin と Cross-Origin-Embedder-Policy: require-corp が付いたページ) にしか許可しません。
    PWA では Service Worker (sw.js) がキャッシュから返すレスポンスにこのヘッダーを付けますが、Service Worker は HTTPS か localhost でしか登録されないため、 LAN の http://192.168.… で開くスマートフォン等では効きません。このチェックを入れるとサーバー側で全レスポンスに付けるので、その環境でも wasm-vips が使えます。
    副作用: COEP を付けたページは、CORS / CORP の無い他サイトの画像やスクリプトを読み込めなくなります。このサーバーが配信するものはすべて同一オリジンなので通常は問題ありませんが、 既定のエンジン (Pica) で十分ならオフのままで構いません。

    ポートと待ち受けの変更はサーバーの再起動で反映されます。

    Basic 認証

    パスワードは bcrypt ハッシュで保存されます (PHP 版 library.php の password_hash と互換)。LAN の外に公開するなら HTTPS のリバースプロキシ (Cloudflare Tunnel、Caddy、nginx 等) を前に置いてください。Basic 認証は資格情報を毎回 base64 で送るだけなので、平文の HTTP では丸見えになります。
